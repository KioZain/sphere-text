# Sphere Typography

Генератор раскладывает текст по 3D-сфере (Three.js) и экспортирует результат
в SVG. Главное правило: в экспортном SVG нет шрифта — только кривые,
повторяющие кривизну сферы.

## Текст: композиция из блоков

Панель разбита на секции **Текст / Настройки / Камера / Цвет**.

Текст — это список блоков (до 4). Каждый блок — отдельная text-area
(многострочная, переносы через Enter; длинные строки переносятся автоматически
по ширине) со своими параметрами: начертание (Regular / Bold), размер
(выпадашка с пресетами как в Figma + ручной ввод) и **интерлиньяж** — расстояние
между строками *внутри* этого блока.

Блоки стекаются по вертикали и центрируются. Управление:

- **«+ Добавить строку»** добавляет блок; при 4 блоках кнопка пропадает.
- Первый (верхний) блок — базовый, его нельзя удалить. У остальных есть крестик.
- Блоки переставляются **drag-and-drop** за ручку слева (⠿) с сохранением
  стилей. Нумерация и доступность удаления считаются по позиции.

Глобальные параметры в «Настройках»: **расстояние между блоками** (промежуток
именно между блоками, не путать с интерлиньяжем внутри блока), **наклон** всей
композиции и **масштаб** — общий множитель, увеличивающий/уменьшающий всю
композицию целиком. Цвет текста — один на все блоки. Отдельный «режим
позиционирования» и сдвиги убраны — всё решается вращением сферы.

## Встроенный шрифт (Regular / Bold)

Проект использует один шрифт — **ALS Chromius**, в двух начертаниях:
`fonts/ALSChromius-Regular.otf` и `fonts/ALSChromius-Bold.otf`. Начертание
переключается селектором «Начертание» (Regular / Bold). Выбор произвольного
системного шрифта и кнопка загрузки шрифтов убраны — ничего нажимать не нужно.

Один и тот же файл шрифта используется в двух местах:

- **Превью** (текст на 2D-холсте, который натягивается на сферу) — шрифт
  подгружается через FontFace API, поэтому Chromius виден даже если он не
  установлен в системе.
- **Экспорт** — тот же файл разбирается через opentype.js, и по контурам букв
  строятся кривые. Раз это буквально один и тот же файл, экспорт всегда
  совпадает с тем, что на сфере.

Добавить ещё вес просто: положить OTF/TTF в `fonts/`, дописать его в `FONT_URLS`
(в `main.js` и `outline.js`) и добавить `<option>` в селектор в `index.html`.

## Сфера без освещения + прозрачный режим

Освещение убрано полностью: материал сферы — неосвещаемый (`MeshBasicMaterial`),
поэтому текстура показывается плоско, в истинных цветах, без бликов и градиентов.
Источников света в сцене нет. Цвет сферы фиксирован — чёрный, отдельной
настройки для него нет.

Тумблер **«Прозрачная сфера (только текст)»** (под выбором цветов) делает тело
сферы прозрачным: остаётся только текст, а фон сферы становится прозрачным.
Задние грани отсекаются, поэтому сквозь просветы виден фон страницы, а не
обратная сторона сферы.

## Камера: фокусное расстояние

Поле **«Фокусное расстояние»** (24–200 мм, по умолчанию 50) задаёт объектив
в привычном 35-мм эквиваленте: three.js считает угол обзора от `filmGauge = 35`.
Рядом — выпадашка с классическим рядом фокусных (24 / 28 / 35 / 50 / 85 / 105 /
135 / 200), ручной ввод тоже работает.

Короткое фокусное — сильная перспектива: камера подходит вплотную, центр сферы
«раздувается», текст выпучивается и буквы по краям строк резко уходят за силуэт.
Длинное — плоская телевик-картинка, зато по кривизне видно почти полную
полусферу. Разница между краями диапазона — примерно 2.5× по площади текста
на экране (видимая часть сферы: 60° на 24 мм против 87° на 200 мм).

Ключевой момент: **размер сферы в кадре не меняется**. При смене фокусного
камера отъезжает или подъезжает так, чтобы сфера занимала ту же долю кадра
(классический dolly zoom), — то есть параметр управляет искажением перспективы,
а не зумом. Собственный зум колесом при этом сохраняется: он хранится как
множитель `zoomFactor` относительно «эталонной» дистанции, а не как абсолютная
координата. Благодаря этому один и тот же ракурс одинаково выглядит в окне
любого размера — что важно для пресетов.

Так как экспорт проецирует точки через ту же камеру, фокусное расстояние
автоматически влияет и на SVG.

Стартовый ракурс смотрит прямо на текст. Это не само собой разумеющееся: центр
текстуры (`texX = ширина/2`) маппится в точку `+X` на сфере, поэтому камера
стоит на оси `+X`, а не на `+Z` — иначе текст был бы виден только срезом
у правого края силуэта.

## Экспорт настроек (для пресетов)

Техническая кнопка **«Экспортировать настройки»** выгружает JSON со всем, что
определяет текущий вид: ракурс камеры (азимут, полярный угол, `zoomFactor`,
фокусное), параметры композиции, цвета, список блоков с их начертанием,
размером и интерлиньяжем, а также размеры текстуры и вьюпорта.

Ракурс пишется углами и множителем зума, а не сырыми координатами, поэтому
пресет, собранный из такого файла, воспроизводит вид независимо от размера окна.
Файл называется `sphere-typography-settings-<дата-время>.json` — можно выгрузить
несколько вариантов и собрать из них набор пресетов.

## Как строятся кривые

1. Текст превращается в контуры глифов через opentype.js.
2. Кривые Безье разбиваются на плотные полилинии (в пиксельных координатах
   текстуры, с той же раскладкой, что и в превью: центрирование, интерлиньяж,
   угол, смещение).
3. Каждая вершина прогоняется через ту же цепочку, что и превью: текстура →
   точка на сфере → проекция камеры. Проекция нелинейная, поэтому буквы реально
   изгибаются по поверхности.
4. Точки на обратной стороне сферы отсекаются, контур режется по силуэту.
5. На выходе — один `<path fill-rule="nonzero">`, поэтому внутренние контуры
   (дырки в буквах) вырезаются корректно. Ни `<text>`, ни `font-family`.

## Запуск (без Node.js)

Нужен только Python 3. Открывать `index.html` файлом нельзя — ES-модули требуют
защищённого контекста, поэтому запуск через локальный http-сервер:

```bash
bash start.sh        # или: python3 -m http.server 8765
```

Открыть в браузере **http://localhost:8765**, ввести текст, при необходимости
повернуть сферу и нажать **«Экспортировать в SVG»**.

## Хостинг на GitHub Pages

Проект — чистая статика, деплоится как есть, без сборки. Все пути относительные,
CDN не используется (three.js и opentype.js завендорены в `vendor/`). GitHub
Pages раздаёт по HTTPS, что даёт защищённый контекст для ES-модулей.

1. Положить содержимое этой папки в корень репозитория (чтобы `index.html` был
   в корне публикуемой папки).
2. Settings → Pages → Source: ветка `main`, папка `/ (root)`.
3. Открыть выданный адрес `https://<логин>.github.io/<репозиторий>/`.

По желанию — пустой файл `.nojekyll` в корне, чтобы отключить обработку Jekyll.
`start.sh` для gh-pages не нужен, но и не мешает.
